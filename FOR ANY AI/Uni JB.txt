================================================================================
DEBUG LIBRARY STACK BEHAVIOR
================================================================================

Stack Level Reference:

    function a()                               -->  Level 3 from c()
        local e = d();                         -->  Level 1 (e = 12345, in stack)
        b();                                   -->  Level 2 (stack ends here during b)
        local g = f();                         -->  Level 3 (g doesn't exist yet)
    end

    function b()                               -->  Level 2 from c()
        c();
    end

    function c()                               -->  Level 1 (current function)
        print(debug.traceback(_,1));           -->  "c", "b", "a", "caller"
        print(debug.info(1, "n"));             -->  "c"
        print(debug.info(2, "n"));             -->  "b"
        print(debug.info(3, "n"));             -->  "a"
        print(debug.getstack(3,1));            -->  12345 (value of 'e' in a)
        table.foreach(getstack(3), warn)       -->  all VALUES on level 3's frame
    end

    function d() return 12345 end
    function f() return "no see in stack!" end

    a();                                       -->  Level 4 from c()

Critical Stack Rules:

1. Stack Levels Count Backwards:
   - Level 1 = Current function (where you call debug.getstack)
   - Level 2 = Function that called current function
   - Level 3 = Function that called level 2
   - Level N = Nth function up the call chain

2. Only Existing Variables Appear:
   - Variables assigned BEFORE the current execution point exist in stack.
   - `local e = d()` exists because d() completed before b() was called.
   - `local g = f()` does NOT exist because f() hasn't been called yet.
   - Variables are only in stack during their function's active execution.

3. debug.getstack() / debug.setstack() Usage:

       debug.getstack(level)               --> array of all VALUES on that frame
       debug.getstack(level, index)        --> VALUE at numeric slot `index`
       debug.setstack(level, index, value) --> writes `value` to numeric slot

   Both functions take a NUMERIC index only. There is no name-string variant.
   `stackVars[i]` is a VALUE, not a name - passing it back as `index` will not
   work. Always iterate by `i` and use `i` as the index.

4. debug.info() Usage:

       debug.info(level, "n")             --> function name at that level
       debug.info(level, "s")             --> source info
       debug.info(level, "l")             --> current line number
       debug.info(level, "nsl")           --> combined info

Practical Application for Hooks:

Inside a `__namecall` hook the level layout is:
- Level 1 = your hook callback
- Level 2 = function that called the namecall'd method (target locals live here)
- Level 3+ = further up the call chain

    local oldNamecall = hookmetamethod(game, "__namecall", function(self, ...)
        local method = getnamecallmethod()
        if method == "Raycast" then
            local stackVars = debug.getstack(2)
            for i = 1, #stackVars do
                local varValue = stackVars[i]
            end
        end
        return oldNamecall(self, ...)
    end)

Variable Visibility Rules:
- Stack slots are populated ONLY during their owning scope's active execution.
- Upvalues are NOT in getstack - use `debug.getupvalue` / `debug.setupvalue`.
- Temporary values (function-call return values not bound to a `local`) don't
  persist in the stack frame.
- Only VALUES bound to active named local variables appear in `debug.getstack`
  - the function returns values, not names.
- Variables assigned AFTER the hook's instruction pointer don't appear yet.
- Identify target variables by heuristics (type checking, value ranges) rather
  than slot index.

================================================================================
ENVIRONMENT EXPOSURE CAVEAT (CRITICAL)
================================================================================

Calling `require` on a script (especially a game ModuleScript) will expose our
executor environment (getgenv(), our globals, hooks, and any state we've placed
there) to that script. The required script runs with access to the same global
environment as the caller, so any sensitive references, hook backups, or
executor-only globals become readable/modifiable by the required module.

Treat `require` on untrusted/game scripts as an environment leak - sandbox
first (via getfenv/setfenv on a script closure, or by loading bytecode in an
isolated env) before requiring if the module is not fully trusted.

Avoid the leak with setthreadidentity(2): before any `require` call on a
game/untrusted ModuleScript, drop the thread identity to 2 so the required
module runs with regular game-script permissions and CANNOT see executor
globals or executor-level capabilities. Restore identity afterward (typically
back to 8):

    setthreadidentity(2)
    local module = require(target_module_script)
    setthreadidentity(8)

Identity 2 is also required when the bypassed/wrapped call internally invokes
`require` on a ModuleScript (e.g. inside a hooked controller function) -
without dropping identity, the loader's permission errors or the env leak will
fire. Always bracket: drop to 2 before, restore to 8 after.

================================================================================
CLOSEST PLAYER HELPER (CANONICAL)
================================================================================

When closest-player-to-cursor-in-fov logic is needed, use the canonical
`getClosestPlayer` helper below. Adapt service references and locals to the
surrounding script's existing variables (`localPlayer`, `userInputService`,
`playersService`, `currentCamera`, `fovRadius`) - the algorithm itself
(viewport projection + 2D mouse-distance pick) is what must stay consistent.

    ---Return the player whose HumanoidRootPart projects closest to the cursor
    ---within fovRadius.
    ---@return Player?, number?, table
    local function getClosestPlayer()
        local closest, closestDist, candidates = nil, math.huge, {}
        local mousePos = userInputService:GetMouseLocation()

        for _, player in ipairs(playersService:GetPlayers()) do
            if player == localPlayer then continue end
            local character = player.Character
            if not character then continue end

            local hrp = character:FindFirstChild("HumanoidRootPart")
            local humanoid = character:FindFirstChild("Humanoid")
            if not (hrp and humanoid and humanoid.Health > 0) then continue end

            local screenPos, onScreen = currentCamera:WorldToViewportPoint(hrp.Position)
            if not onScreen then continue end

            local dist = (Vector2.new(screenPos.X, screenPos.Y) - Vector2.new(mousePos.X, mousePos.Y)).Magnitude
            if dist <= fovRadius then
                table.insert(candidates, { player = player, dist = dist, screenPos = screenPos })
            end
        end

        for _, info in ipairs(candidates) do
            if info.dist < closestDist then
                closest = info.player
                closestDist = info.dist
            end
        end

        return closest, closestDist, candidates
    end

ANTI-CHEAT BYPASS GUIDANCE
================================================================================

USE THESE EXAMPLES TO FIND METHODS AGAINST THE ANTICHEAT - NOT TO FULLY COPY.
THEY WILL NOT WORK FOR EVERY ANTICHEAT. Every example is one specific AC build
at one point in time. Slot indices, key counts, source paths, constant lists,
table sizes, timing windows, upvalue counts, and shape predicates all shift
between AC builds, between game updates, and sometimes between sessions.

If you recognize the target AC as a documented one - DO NOT REUSE THE
DOCUMENTED BYPASS. The fact that a bypass is documented usually means it has
since been patched or detected. Re-using a documented bypass against the same
AC family is the fastest way to get caught. Treat the documented approach as a
*starting hypothesis* - re-map the AC from scratch, derive new shape
predicates, design a fresh bypass that doesn't share fingerprints.

What to extract from the examples below:
- The *family of techniques* (GC walking, source/constant shape-matching,
  metatable decoys, sentinel locking, foreign-state RCE via run_on_actor,
  etc.).
- The *pattern of using CONFIG blocks + shape predicates* so re-targeting a new
  AC is editing one block, not rewriting the bypass.

What NOT to do:
- Do NOT copy any literal value (slot index, key count, size threshold, source
  substring, constant list, timing) into a new bypass.
- Do NOT assume the example's AC variant matches the AC in front of you -
  re-map it.
- Do NOT assume what worked in the example will work for you - validate
  against your target.
- Do NOT reuse a documented bypass on the AC it was documented against - find
  a fresh angle.

Re-map every detection on the actual target. The only universally portable
parts are the predicate-driven structure (CONFIG + shape predicates) - never
the specific values.

Handshake / heartbeat channels:
Some ACs ship a handshake / heartbeat / pulse / liveness channel alongside
their detection logic - observable shapes include a low-frequency
RemoteFunction:InvokeServer with no detection payload, or a foreign-state
thread that pumps via coroutine.wrap + task.wait. Whether a channel is purely a
liveness pulse or also carries detection payloads, and what server behavior it
gates, is target-specific - investigate before deciding whether to leave it
untouched, intercept it, or replay it.

ANTI-CHEAT EXAMPLE 1 - ENCODED REMOTE WITH UUID/HASH/SALT/ENCODER UPVALUES
--------------------------------------------------------------------------------

Scenario: Some games route sensitive remotes through a controller script that
wraps the RemoteEvent behind an Encoder and validates with UUID, Hash, Salt.
The remote name is dynamic - you can't WaitForChild it.

Pattern:
1. Walk getgc(false) for functions.
2. Use debug.info(Function, "s") to filter by source containing the controller
   name AND a marker substring - both CONFIG values.
3. debug.getupvalues(Function) and discover UUID, Hash, Salt, Encoder by
   SHAPE, not by hardcoded slot index. Upvalue ordering shifts across game
   updates / Luraph builds.
4. Build the remote via Encoder.RemoteEvent(UUID, Salt).
5. Fire with the exact argument shape the legitimate controller uses.

Key takeaways:
- debug.info(fn, "s") + source-substring matching is the primary way to
  locate the controller. Keep substrings in CONFIG.
- Discover UUID/Hash/Salt/Encoder by SHAPE (string length, table contents,
  callable field presence), never by hardcoded upvalue slot.
- Walk upvalues dynamically via pcall(debug.getupvalue, fn, i) until it
  errors - never with for i = 1, <hardcoded N> do.
- Network keys frequently live as nested values inside an upvalue table -
  search nested tables, don't assume top-level only.

--------------------------------------------------------------------------------
ANTI-CHEAT EXAMPLE 2 - GETFENV METAMETHOD TRAP + LURAPH NETWORK MODULE
--------------------------------------------------------------------------------

Scenario: A bootstrapper defines a network module obfuscated with Luraph. An
AC may install a metamethod trap that calls getfenv from inside any network
method and reads the returned env.

Pattern:
1. Snapshot getrenv() and build a FakeEnv with __index = RobloxEnv so missing
   keys still resolve back to the real env.
2. hookfunction RobloxEnv.getfenv (NOT the executor's getfenv) so game-side
   calls go through the hook.
3. Inside the hook, walk the call stack with debug.isvalidlevel to terminate
   dynamically (no hardcoded depth) and check whether any frame's source
   matches the configured Driver substring. If yes, return FakeEnv. Otherwise,
   fall through.
4. Locate the GameTable by filtering for a sentinel function name (per-game
   CONFIG) and discovering the table-typed upvalue dynamically.
5. For privileged calls bracket with setthreadidentity(2) -> call ->
   setthreadidentity(8).

Key takeaways:
- Game-side code calls getrenv().getfenv (the Roblox-env one), not the
  executor's getfenv. Hook the right one.
- Use __index = RobloxEnv on the fake env so any field access on it resolves
  to the real env. A bare {} lacks every global.
- Source-matching with debug.info(Index, "s"):find(<sourceSubstring>) is
  stable even when function names are mangled by an obfuscator.
- Walk the call stack via while debug.isvalidlevel(i) do ... i = i + 1 end -
  depth varies per game.
- Use filtergc("function", {Name = <sentinelFnName>}, true) then walk its
  upvalues with pcall(debug.getupvalue, fn, i) until error and pick the first
  one matching your shape predicate.
- setthreadidentity(2) is required when the bypassed call internally invokes
  require on a ModuleScript. Always restore to 8 after.

--------------------------------------------------------------------------------
ANTI-CHEAT EXAMPLE 3 - BAN-TABLE METATABLE TRAPS + DETECTION-PROTO NEUTRALIZATION
--------------------------------------------------------------------------------

Scenario (illustrative): Some games store ban triggers as plain Luau tables
that the AC writes to when a violation is detected. Detection logic may live
as nested protos inside a single container script - each proto checking for
one exploit category.

Pattern:
1. Wrap entire bypass in LPH_JIT_MAX(function() ... end)(). Bail with Kick
   early if not in the right place / not spawned in.
2. Ban-table neutralization: walk getgc(true) for tables. Identify ban-table
   containers by their *shape* - predicates live in CONFIG, so slot indices
   and table sizes never appear as bare literals in the body.
3. Replace each ban table's metatable with
   {__index = function() end, __newindex = function() end} - reads return nil
   and writes are dropped.
4. Detection-proto neutralization: walk getgc(false) for functions, skip
   iscclosure and isexecutorclosure. Match scripts whose source contains
   CONFIG.detectionScript. Walk every proto via
   pcall(debug.getproto, fn, p) until it errors (no hardcoded cap), and test
   each proto's constants against every entry in CONFIG.detectionSignatures.
5. Use LPH_NO_VIRTUALIZE for utility helpers; LPH_NO_UPVALUES for replacement
   closures so they have zero upvalues.
6. Use cloneref on services the script holds onto.

Key takeaways:
- Identify ban-table containers by shape, not by name. Use stable invariants
  (anchor at slot 1 is an Instance with a known Name, slots 1/2 equal
  Character/Humanoid, etc.) wrapped in CONFIG predicates.
- setmetatable(banTable, {__index = function() end,
  __newindex = function() end}) makes reads return nil and writes a no-op.
  Don't raise from the metamethod.
- For detection protos, NEVER hook the outer function. Use
  debug.getproto(outer, i) and hook the proto directly.
- Match protos by their constants list, not by name (Roblox script constants
  are stable; names may be mangled).
- LPH_NO_UPVALUES(function() return end) produces a hook with zero upvalues,
  which hookfunction accepts regardless of the original proto's upvalue count.
- cloneref(game:GetService("Players")) returns a distinct reference, useful
  when an AC compares Players references via weak-table identity.

--------------------------------------------------------------------------------
ANTI-CHEAT EXAMPLE 4 - LURAPH-VIRTUALIZED + FOREIGN-STATE METATABLE POLL
--------------------------------------------------------------------------------

Scenario: An AC ships as a nil-parented LocalScript running Luraph-virtualized
bytecode. Main runtime can live in a foreign Lua state - an Actor visible only
via getdeletedactors()[1] or in foreign threads at identity 8 (getallthreads
minus isourthread). One observable polling shape: the foreign loop reads
getrawmetatable(game).__namecall each tick and compares against a cached
baseline.

Pattern:
1. Identify match by SHAPE, not by literal size. getnilinstances() finds the
   AC LocalScript by source/name predicates from CONFIG. Definitive
   confirmation: filtergc("function",
   {Constants=CONFIG.PROBE_CONSTANTS, IgnoreExecutor=true}, false) returns
   LClosures whose upvalue tuple satisfies CONFIG.kickProbeShape.
2. Neutralize the report path BEFORE any other modification. Walk the probe's
   upvalues dynamically for the nil-parented RemoteEvent, then
   debug.setupvalue(probe, <discovered-slot>, Instance.new("RemoteEvent")) +
   hookfunction(probe, function() end). Never lift upvalue[1] directly.
3. Lock the violation sentinels (if the AC uses this pattern). Master
   container as upvalue across many worker closures, with shared single-key
   {[1]=false} tables.
4. Install a decoy metatable on game so subsequent metamethod mutations go
   via rawset on the decoy.
5. Mutate __namecall via rawset on the decoy:

       local prev = rawget(decoy, "__namecall")
       local wrapper = newcclosure(function(self, ...)
           if checkcaller() then return prev(self, ...) end
           return handler(self, ...)
       end)
       pcall(setstackhidden, wrapper, true)
       pcall(debug.setinfo, wrapper, "s", "[C]")
       pcall(debug.setinfo, wrapper, "n", "")
       rawset(decoy, "__namecall", wrapper)

6. Watchdog re-running steps 2 + 3 for CONFIG.WATCHDOG_DURATION at
   CONFIG.WATCHDOG_INTERVAL cadence - handles target closures or sentinels
   that appear after the initial install pass.

Key takeaways:
- Decoy-metatable technique: setrawmetatable(game, decoy) with all fields
  copied via rawset, then mutate __namecall on the decoy via rawset instead of
  hookmetamethod. Investigate before applying.
- Find master containers by SHAPE - cnt >= CONFIG.SENTINEL_MIN_KEYS plus
  >= CONFIG.SENTINEL_MIN_CHILDREN size-1 {[1]=false} children. Addresses
  rotate per session.
- Heartbeat-bridge BindableEvents (single foreign subscriber, no payload) often
  serve as a liveness channel. Verify per-target.
- Foreign Heartbeat connections may not be the actual pump path. Some ACs
  self-pump on a coroutine driven by task.wait, captured as a bytecode upvalue.
- GC visibility timing: lazily-spawned closures may not be present at install.
  Schedule a watchdog if your install pass misses something.
- Foreign-state RCE primitive: when getactors() == 0 but
  getdeletedactors()[1] exists, run_on_actor(getdeletedactors()[1], code)
  works for executing code inside the AC's foreign Lua state.
- Some ACs pre-resolve method tokens (FireServer, Kick, Move, IsA,
  GetService) into bound C closures and call them as methodFn(self, args)
  instead of self:method(args). A __namecall hook will not see calls made
  through the dot form.

ANTI-CHEAT EXAMPLE 5 - LOGSERVICE.MESSAGEOUT TRAP + ENCODED-REMOTE RESOLVER
--------------------------------------------------------------------------------

Scenario: The game ships an AC that subscribes to LogService.MessageOut to
catch warns/errors thrown by exploit hooks. The AC's listener closure captures
the detection table as one of its upvalues. Separately, the gameplay layer
wraps every RemoteEvent behind a two-stage encoder: a function in the Net
module captures {enc1_fn, enc2_fn, salt1, salt2} as one of its upvalues.

Pattern:
1. Inspect LogService.MessageOut connections. Walk
   getconnections(LogService.MessageOut), pull conn.Function, then walk its
   upvalues dynamically for one whose value matches CONFIG.isDetectionTable
   (typically a table with a callable [0]).
2. Net-encoder lift. Walk getgc(true) for functions whose source matches the
   Net module path (CONFIG). Walk the function's upvalues dynamically for one
   matching the encoder shape: a table where rawget(t, 1) and rawget(t, 2) are
   both functions AND t[0] is NOT a function.
3. Replay encoding client-side. The two-stage hash is
   enc1Out = enc2(name, salt1) -> buff = buffer.fromstring(enc1Out) ->
   final = enc1(buff, buffer.fromstring(salt2 .. salt1)) ->
   NetFolder:FindFirstChild("RE/" .. final).

Key takeaways:
- LogService.MessageOut is a global signal whose getconnections lists every
  subscriber across the process - useful for investigating who is listening
  for warns/errors.
- Detection-table shape (when present): a table upvalue with callable [0]
  (dispatch) and a table [1] (state).
- __newindex traps over the detection table drop writes while letting you log
  the payload.
- Encoded-remote pattern: enc2(name, s1) -> buffer.fromstring -> enc1(buff,
  buffer.fromstring(s2..s1)). The two encoders + two salts always travel
  together inside one upvalue table on a Net-module function.
- Net-module source match: info.source == CONFIG.netModuleSource (note the
  leading = that debug.getinfo prepends) is the exact match.
- clonefunction the encoders rather than calling them through the original
  references.
- Always run print(Class.Convert(uv, true)) on the upvalue table the first
  time you encounter a new game's AC.

--------------------------------------------------------------------------------
ANTI-CHEAT EXAMPLE 6 - LOGGING BAN-TRAP VARIANT (SLOT-0 ANCHORED CONTAINER)
--------------------------------------------------------------------------------

Scenario: Same family as Example 3. Two distinct container shapes:
- Container A is anchored by both Character AND Humanoid, but at slots 1 and
  0 respectively. Slot 0 anchor is unusual: pairs doesn't iterate slot 0 by
  default - predicates that only walk pairs will miss this anchor.
- Container B is anchored by an Instance named "Remotes" at slot 1.

The distinguishing feature is the LOGGING-style trap. Instead of silently
no-op'ing, the trap writes the AC's ban payload to the rconsole via
HttpService:JSONEncode before discarding it. Once mapping is done, swap the
logging trap for a silent one.

Key takeaways:
- Slot-0 anchors are real. Luau tables accept any key including 0 and negative
  integers; pairs is implementation-defined for non-positive-integer keys. Use
  rawget(t, 0) to validate, never rely on pairs to find it.
- Log before you neutralize. Instrumented __index / __newindex traps
  rconsoleprint the violation payload via HttpService:JSONEncode(value) before
  dropping it. Once mapped, swap for function() end.
- Tag every trap with a unique ID so you can correlate Index vs Ban-Attempt
  entries when multiple ban tables are live.
- Discover ban-table slots inside a container by SHAPE, not hardcoded slot
  index. Walk every table-typed slot that isn't one of the known anchors.
- rawset(banTable, 1, nil) clears the violation-flag slot before metatable
  install for ACs that seed slot 1 with false.
- Bail loud, not soft. If neither container was found, Kick rather than
  continuing.

BUILDING YOUR OWN APPROACH
--------------------------------------------------------------------------------

The examples above are *specific* solutions to *specific* games at specific
points in time. The next AC you encounter will likely look nothing like any of
them - it might use a coroutine-based detection loop, store flags in a
BindableFunction.OnInvoke callback, validate via a per-tick rolling hash, ship
its checks inside an Actor on a parallel VM, etc.

Use the examples as a vocabulary of building blocks (getgc walking, source/
constant matching, upvalue/proto extraction, metatable traps, env spoofing,
identity bracketing, cloneref, setrawmetatable decoy, sentinel locking,
foreign-state RCE via run_on_actor/getdeletedactors). Then look at what the
*actual* game is doing - read its scripts, inspect its GC, identify where the
validation happens - and design a bypass that fits *that* game.

================================================================================
METATABLE HOOKING PATTERNS
================================================================================

Why metamethods matter:
    Roblox uses metatables everywhere. Almost every Instance has a metatable
    with metamethods. By hooking these metamethods you can intercept and modify
    how the game works. Metamethods are the foundation of how exploiting works.

    - Metatables control the behavior of tables/objects.
    - Metamethods are the functions inside metatables.
    - getmetatable(obj) gets an object's metatable.
    - setmetatable(tbl, meta) sets a metatable on a table.
    - hookmetamethod() safely hooks a metamethod.
    - newcclosure() wraps your function to make it harder to detect.

Hooking with hookmetamethod (preferred):

    local oldNamecall
    oldNamecall = hookmetamethod(game, "__namecall", function(self, ...)
        local method = getnamecallmethod()
        print("method called:", method)
        return oldNamecall(self, ...)
    end)

Full control example (hooking __index, __newindex, and __namecall):

    local meta = getrawmetatable(game)
    setreadonly(meta, false)
    local oldIndex = meta.__index
    local oldNewindex = meta.__newindex
    local oldNamecall = meta.__namecall

    meta.__index = newcclosure(function(self, key)
        return oldIndex(self, key)
    end)

    meta.__newindex = newcclosure(function(self, key, value)
        return oldNewindex(self, key, value)
    end)

    meta.__namecall = newcclosure(function(self, ...)
        return oldNamecall(self, ...)
    end)
    setreadonly(meta, true)

--------------------------------------------------------------------------------
__index HOOKING
--------------------------------------------------------------------------------

__index triggers when you READ a value: local x = object.Property

When to use __index:
    - Logging what properties scripts are trying to read.
    - Spoofing values to make anti-cheats think everything is normal.
    - Hiding certain properties from being accessed.
    - Bypassing detection by returning fake data.

Rules:
    - Always save the original __index before replacing it.
    - Use return oldIndex(self, key) to get the actual value.
    - self is the object being accessed, key is the property name.

Anti-detection example (spoofing WalkSpeed):

    local oldIndex
    oldIndex = hookmetamethod(game, "__index", function(self, key)
        if self:IsA("Humanoid") and key == "WalkSpeed" then
            return 16
        end
        return oldIndex(self, key)
    end)

GetAttribute spoof (mirrors REFERENCE_SCRIPT pattern - method-name match):

    local oldNamecall
    oldNamecall = hookmetamethod(game, "__namecall", function(self, ...)
        local method = getnamecallmethod()
        if method == "GetAttribute" and select(1, ...) == "Recoil" then
            return 0
        end
        return oldNamecall(self, ...)
    end)

--------------------------------------------------------------------------------
__newindex HOOKING
--------------------------------------------------------------------------------

__newindex triggers when you WRITE a value: object.Property = 50

When to use __newindex:
    - Preventing certain properties from being changed.
    - Logging property modifications.
    - Modifying values before they are set.
    - Bypassing anti-cheats that check for property changes.

Rules:
    - Always save the original __newindex before replacing it.
    - Use return oldNewindex(self, key, value) to actually set the property.

Property protection example:

    local oldNewindex
    oldNewindex = hookmetamethod(game, "__newindex", function(self, key, value)
        local blocked = {"WalkSpeed", "JumpPower", "Health"}
        for _, prop in pairs(blocked) do
            if key == prop then return end
        end
        return oldNewindex(self, key, value)
    end)

--------------------------------------------------------------------------------
__namecall HOOKING
--------------------------------------------------------------------------------

__namecall triggers when you use : syntax: object:Method(args).
Regular . calls (object.Method(object, args)) do NOT trigger __namecall.

When to use __namecall:
    - Hooking remote events to see what data is being sent.
    - Blocking certain method calls (Kick, Destroy, etc).
    - Modifying arguments before they reach the actual method.
    - Bypassing anti-cheats that rely on method calls.

Rules:
    - Always save the original __namecall before replacing it.
    - Use return oldNamecall(self, ...) to call the original method.
    - Pair with getnamecallmethod() to know which method was called.
    - self is the object the method was called on, ... contains all arguments.

Modifying arguments example:

    local oldNamecall
    oldNamecall = hookmetamethod(game, "__namecall", function(self, ...)
        local method = getnamecallmethod()
        local args = {...}
        if method == "FireServer" and self.Name == "RemoteEvent" then
            args[1] = "modified data"
            return oldNamecall(self, unpack(args))
        end
        return oldNamecall(self, ...)
    end)

LocalPlayer Kick/Destroy bypass (mirrors REFERENCE_SCRIPT pattern):

    if not game:IsLoaded() then game.Loaded:Wait() end
    local localPlayer = game:FindService("Players").LocalPlayer

    local originalKick
    originalKick = hookfunction(localPlayer.Kick, newcclosure(function(player, reason)
        if player == localPlayer then return end
        return originalKick(player, reason)
    end))

    local originalDestroy
    originalDestroy = hookfunction(localPlayer.Destroy, newcclosure(function(player)
        if player == localPlayer then return end
        return originalDestroy(player)
    end))

    local originalNamecall
    originalNamecall = hookmetamethod(localPlayer, "__namecall", newcclosure(function(object, ...)
        local method = getnamecallmethod()
        if object == localPlayer and (method == "Kick" or method == "Destroy") then
            return
        end
        return originalNamecall(object, ...)
    end))

Avoid `nonamecall` - limited executor support. Prefer the dot-indexing pattern.

--------------------------------------------------------------------------------
tostring
--------------------------------------------------------------------------------

Converts anything into a string. Essential for nil and Instance safety.

    local number = 123
    print(tostring(number)) -- "123"

    local part = workspace.Part
    print(tostring(part)) -- "Part"

    -- nil safety
    local value = nil
    print(tostring(value)) -- "nil"
    print("Value: " .. value) -- ERROR (can't concatenate nil)

--------------------------------------------------------------------------------
typeof
--------------------------------------------------------------------------------

Better than type() for Roblox types - type() returns "userdata" for all Roblox
types, typeof() returns the actual type name.

    print(type(workspace))      -- "userdata"
    print(typeof(workspace))    -- "Instance"
    print(typeof(Vector3.new(0,0,0)))   -- "Vector3"
    print(typeof(Enum.KeyCode.W))       -- "EnumItem"

Common types: Instance, Vector3, CFrame, Color3, EnumItem, plus normal Lua
types.

    if typeof(object) == "Instance" and object:IsA("RemoteEvent") then
        print("found a remote:", object.Name)
    end

--------------------------------------------------------------------------------
nil vs false
--------------------------------------------------------------------------------

Both falsy but NOT the same.
    nil   = something doesn't exist or hasn't been set.
    false = an actual boolean intentionally set to false.

    local x = nil
    local y = false
    print(x == false) -- false
    print(x == nil)   -- true

To check specifically:

    if value == nil then ... end       -- doesn't exist
    if value == false then ... end     -- specifically false
    if not value then ... end          -- catches BOTH

Table key difference:

    local t = {test = false}
    print(t.test)   -- false (exists)
    print(t.random) -- nil (doesn't exist)

--------------------------------------------------------------------------------
task.wait vs wait
--------------------------------------------------------------------------------

Use task.wait. wait() is deprecated and throttled (30ms minimum).

    task.wait(0.01)  -- actually waits 0.01 seconds
    task.wait()      -- one frame
    task.spawn(fn)   -- run on a new thread immediately
    task.defer(fn)   -- next frame
    task.delay(t,fn) -- after delay
